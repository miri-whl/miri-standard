Install from the index

The site also serves a package index, so pip can fetch and verify the wheel in one step:

pip install --index-url {{ site.site_url }}/simple/ miri-standard-checks

Verify what you downloaded

A definitions package is a supply-chain root: reweight one MUST to zero and every wheel passes. Three things let you check it without trusting the host.

  1. The file hash. The index above carries the wheel's sha256, so pip install --index-url verifies what it downloads; sha256sum -c SHA256SUMS checks it out of band. Two builds of one tag on one machine produce identical bytes, because entry timestamps are fixed at write time. The wheel is not reproducible across setuptools versions, which are unpinned, so a rebuild months later may differ.
  2. The wheel pins its own source. Inside the wheel, manifest.json carries checks_commit_sha (the full 40-character commit, never a tag, because a tag is a movable label) and content_sha256 over every definition and schema in sorted order. Recompute it from the source tree at that commit and it must match.
  3. The build attests its provenance. The release job records it for the wheel (gh attestation verify).

How an artifact gets here

Nothing on this page is uploaded by hand. A release tag pushes to {{ site.artifacts[0].workflow }}, which runs the same validators the repository gates on (make validate, make consistency), builds the wheel with {{ site.artifacts[0].built_by }}, attests it, and attaches it to the release for that tag. When the reference linter is available to the build, the job also scores the wheel and fails the release on a low score. The linter is in development and not yet public. The repository stays the source of truth; this is a derived output, like this site.
